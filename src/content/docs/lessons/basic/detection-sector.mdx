В уроке [«Радиус обнаружения»](../radar/) турель замечала игрока по
расстоянию — ближе радиуса или нет. Но бывает нужно обнаружение по
направлению: например, игрок должен попасть не в любую точку вокруг,
а именно в **сектор** — клин между двумя лучами, выходящими из одной
точки.

Сектор задают два угла: первый луч — начало, второй — конец. Между
ними по часовой стрелке и лежит сектор. Если лучи поменять местами,
получится другой, дополняющий сектор — та же пара лучей, но
проверяется уже другая сторона.

## Угол на игрока

Это мы уже умеем — как в уроке [«Угол вектора»](../vector-angle/), и
сразу в радианах, без перевода в градусы:

```rust
let dx = mouse_x - center_x;
let dy = mouse_y - center_y;
let mouse_angle = dy.atan2(dx);
```

## Подвох на границе полного оборота

Напрашивается просто сравнить: `sector_start <= mouse_angle &&
mouse_angle <= sector_end`. Работает, пока сектор не переходит через
точку, где оборот обрывается и начинается заново. Если для наглядности
представить это в градусах: `sector_start = 350°`, `sector_end = 10°`
— совершенно нормальный сектор в 20°, просто захватывающий ноль.
Курсор под углом `5°` явно внутри него на глаз, но `5 <= 350` неверно
— наивное сравнение скажет «снаружи», ошибочно. (Дальше в коде таких
чисел не будет — там всё в радианах, градусы были только для примера.)

Решение уже знакомо — [«Угол от 0 до 360°»](../angle-normalize/),
только применённое не один раз, а дважды. Вместо сравнения двух
абсолютных углов меряем, **сколько радиан по часовой стрелке** от
начала сектора — и до курсора, и до конца сектора:

```rust
use std::f32::consts::PI;

// Сколько радиан по часовой стрелке от sector_start до sector_end —
// весь сектор целиком.
let sector_span = (sector_end - sector_start).rem_euclid(2.0 * PI);
// Сколько радиан по часовой стрелке от sector_start до курсора.
let relative = (mouse_angle - sector_start).rem_euclid(2.0 * PI);

let inside = relative <= sector_span;
```

`rem_euclid` гарантирует, что оба числа лежат в `0..2π`, поэтому
`relative <= sector_span` работает одинаково, пересекает сектор точку
обрыва оборота или нет — разбирать случаи отдельно не нужно.

## Рисуем сектор

Сами лучи рисуются обычной `draw_line`, только достаточно длинной,
чтобы выйти за край экрана любого размера — та же идея, что и у пули
до выстрела в уроке [«Турель стреляет»](../turret/): не считаем точную
длину, просто берём число с запасом.

Два луча сами по себе неоднозначны — непонятно, какая из двух сторон
между ними проверяется. Поэтому добавлен третий, короткий жёлтый
отрезок — ровно посередине сектора. Он не участвует в проверке и ничего
не считает заново, кроме уже посчитанного `sector_span`, — просто
подсказка на глаз, какая сторона имеется в виду.

## Что здесь происходит

- `mouse_angle` — угол на курсор в радианах, тем же `atan2`, что и в
  [«Угле вектора»](../vector-angle/) — без перевода в градусы, прямо
  то, что он возвращает.
- `sector_span` и `relative` — оба в `0..2π` благодаря `rem_euclid`,
  поэтому `relative <= sector_span` верно определяет попадание в
  сектор при любых `sector_start`/`sector_end`, даже если сектор
  переходит через точку обрыва оборота.
- Серые лучи — границы сектора, намеренно очень длинные, чтобы
  выходить за край экрана.
- Жёлтый отрезок — только для наглядности, какая сторона проверяется;
  на `inside` он не влияет.
- Турель красная, пока курсор внутри сектора, иначе синяя — та же
  идея, что и в [«Радиусе обнаружения»](../radar/).
