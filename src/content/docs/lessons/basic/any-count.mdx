В уроке [«Цикл for»](../for-loop/) количество кружков было зашито в код —
ровно пять. Цикл там избавил нас от пяти одинаковых строк `draw_circle`,
но число кружков всё равно было известно заранее, ещё когда мы писали
код.

У `for` есть вторая, более важная сила: один и тот же код работает для
**любого** количества, каким бы оно ни оказалось. Циклу всё равно,
сколько раз повторяться — пять, один или десять: он просто проходит
диапазон `0..COUNT`, сколько бы чисел в нём ни было.

```rust
// Тело цикла не изменилось ни на строку — другим стало только COUNT.
for i in 0..COUNT {
    // ...
}
```

Код при этом остаётся ровно тем же самым, что и в [«Цикле
for»](../for-loop/) — тот же `START_X`, тот же `STEP`, то же тело
цикла. Меняется только само число `COUNT`, и теперь оно приходит не
захардкоженным, а из поля ниже.

## Что здесь происходит

- `COUNT` — то же самое число, что и в уроке [«Цикл for»](../for-loop/),
  но теперь его задаёт поле ниже, а не фиксированное значение в коде.
- `for i in 0..COUNT` не изменился ни на символ — весь урок как раз о
  том, что этому циклу не нужно знать заранее, сколько кружков
  рисовать, чтобы правильно отработать.
- Поставь `count` в 1 — цикл просто выполнится один раз, нарисовав
  единственный кружок, без каких-либо особых случаев в коде.
- `count` ограничен десятью — чтобы при фиксированном шаге кружки
  гарантированно умещались на экране демки, а не уезжали за край.
